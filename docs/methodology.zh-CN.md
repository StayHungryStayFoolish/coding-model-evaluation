# 评测方法说明

- 评测围绕 33 个定制业务场景，分别呈现 API、受控工程开发与 Antigravity 的结果。
- 同一轨道使用相同任务要求和验收标准，由编译运行、测试和指令约束检查评分。
- 三次运行观察同一场景的稳定性，不增加独立业务场景数。

## 数据集与业务能力

数据集由任务要求、初始代码和验收检查构成，围绕开发工作设计，不是从客户生产流量随机抽样所得。

| 类别 | 不同场景数 | 具体检查内容 |
|---|---:|---|
| 业务模块与系统开发 | 9 | 日志、依赖调度、缓存与限流、撮合、协议、规则与 WebAssembly 生成 |
| 持续需求演进 | 6 | 每项目五轮需求：遥测、响应式状态、事务存储、服务恢复、查询引擎与语言工具 |
| 存量维护与质量提升 | 6 | 长代码排障、局部补丁、单测生成、安全修复、语言迁移与 SQL |
| 前后端与跨模块开发 | 6 | 界面交互、后端并发、审批接口、数据与页面状态、跨模块修改与重构 |
| 升级、交付与运行维护 | 6 | 依赖兼容、构建修复、数据迁移、CI 门禁、启动健康检查与日志排障 |

前端检查包括浏览器行为与输入安全；后端检查覆盖服务逻辑、事务行为与并发配额；全栈检查覆盖审批接口、数据库操作与页面状态。报告按实际测试对象描述，不将服务层检查写成完整生产部署测试。

## 三种测试方式

| 轨道 | 数量 | 生成、反馈与验收 | 配置 |
|---|---|---|---|
| API 直接调用 | 21 场景 × 3 次 × 4 模型，共 540 次生成 | 单轮任务一次生成；六个项目按五轮需求递进并保留历史。生成时没有编译或测试反馈，生成后执行验收。 | Argon HIGH；Claude adaptive + high；输出上限 64,000 tokens |
| 受控工程开发 | 12 任务 × 3 次 × 4 模型，共 144 会话 | 独立工作区、统一工具接口，可查看公开检查反馈并修复；最终以隐藏功能检查和指令约束验收。最多六次模型响应、十五分钟会话。 | Argon HIGH；Claude adaptive + high；输出上限 32,000 tokens |
| Antigravity | 复用前述 21 场景，每个参测模型一组归档结果 | 工具调用结果单独统计，报告使用的合规记录在生成时没有执行 shell、编译器或测试。Sonnet 的四个项目按规则重新测试。Haiku 未参加。 | 底层参数由工具管理，公开材料不提供内部配置 |

21 个 API 场景中有 9 个单轮模块、6 个五轮项目和 6 个维护任务，因此每模型每次运行有 9＋30＋6＝45 次生成；四模型三次合计 540 次生成。完整场景成功率的分母是每模型 21×3＝63，不是 135 次生成。工程分母为每模型 12×3＝36。公开数据包含 252 条 API 场景运行记录和 144 条工程记录，共 396 条。

API 实际配置字段如下，工程轨道将输出上限改为 32,000：

```json
{"generationConfig":{"maxOutputTokens":64000,"thinkingConfig":{"thinkingLevel":"HIGH"}}}
```

```json
{"max_tokens":64000,"thinking":{"type":"adaptive"},"output_config":{"effort":"high"}}
```

这些只是生成配置字段，不是完整请求示例。跨厂商相同档位名称不代表相同计算预算。其他采样参数使用服务默认值，本报告没有测试低档或最高档的跨档位比较。

## 如何评分，谁是裁判？

**没有 primary / secondary judge model。** 分数来自执行代码并检查预期行为和明确约束。GPT-6 Astra（high）辅助数据复核与报告分析，不负责给答案评分；这不等于独立第三方认证，也不用于推断测试集作者身份。

| 指标 | 定义 |
|---|---|
| API 唯一功能检查 | 每模型每次运行 361 项无歧义检查，独立检查只计一次 |
| 历史回归 | 每模型每次运行 180 项，检查五轮项目是否保留先前功能，与唯一功能检查分别统计 |
| API 完整场景成功 | 整个场景的所有适用功能和回归检查通过 |
| 工程隐藏功能检查 | 每任务 10 项，每模型每次运行 120 项 |
| 工程指令检查 | 每任务 4 项：要求的接口、允许编辑的文件、禁止的改动/依赖、交付与测试声明 |
| 工程完整成功 | 最终工作区通过所有功能和指令检查 |
| 首次修改即成功 | 第一次完整修改就满足最终验收，区别于反馈修复后的成功 |

缺失输出、编译失败、预算耗尽不缩小分母。同一场景的多个断言和重复运行不是额外独立业务场景。

一项语言作用域检查存在题意与测试歧义，统一从功能评分中排除，分母从 362 改为 361。工程指令检查也统一纠正了注释和初始构建产物造成的误判；公开工程数据同时保留原始与修正后的指令分数和完整成功标记。

最终归档的哈希校验只能说明文件完整性，不能单独证明所有检查在运行前冻结。复核发现赛前清单对部分检查文件覆盖不足，前端依赖也存在版本差异，因此报告不声称全部材料已完成独立的赛前冻结验证。

## 费用、耗时与解读

费用以实际用量和报告注明的价格计算，包含计费思考输出、缓存读取和反馈修复调用；不含人工、运行环境、尚未进行的修复，也不估算缺少可用计费记录的失败传输请求。这不是账单对账。

每成功任务费用＝任务集全部计入的调用费用÷完整成功次数。分子包含实测失败任务与反馈修复的费用，但不能将该值理解为保证修好所有剩余失败的报价。

价格以 2026-10-14 核验的 Global 调用价格为依据。Argon 采用截至 2026-11-30 的优惠有效价：输入 / 输出 / 缓存读取每百万 Token $2 / $10 / $0.10。Opus 为 $4 / $20 / $0.20；Sonnet 为 $2 / $10 / $0.10；Haiku 在本次低于 100K 的输入范围为 $0.10 / $0.50 / $0.01。Argon 后续标准输入 / 输出价为 $4 / $20，不能直接沿用优惠期节省比例。来源：[Google Cloud](https://cloud.google.com/vertex-ai/generative-ai/pricing)、[Anthropic](https://platform.claude.com/docs/en/about-claude/pricing)。

API 耗时按单次请求统计；工程耗时按完整会话统计，两者不可混为同一个指标。Antigravity 缺少可比的费用和时间记录，保留空值。

报告结合成功行为、错误类型与业务影响解释差异，不将小样本均值差异写成稳定领先，也不将“不显著”写成能力等价。增加 Token 或尝试次数可能有帮助，但没有实测的补齐成本不会计入 Argon 节省额，预算内失败也不代表模型永久无法完成。
